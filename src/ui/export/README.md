# Stage 4 — Local Audit Report Export

## Purpose

Allow users to export the complete results of a
successful Workflow Inspector audit as a local JSON file.

This is Step 4.9.

Export does not execute or modify workflows.

## Scope

Implemented:

- JSON report creation
- Versioned report format
- Complete finding export
- Local browser download
- Fixed download filename
- Safe download-error message
- Export after successful audits
- Export of audits with zero findings
- Separation from visual filters

Not implemented:

- PDF export
- CSV export
- Export of only visible findings
- Import of exported reports
- Cloud storage
- Report sharing
- Workflow repair
- Automatic report generation

Report creation and download:

## Input contract

The export function accepts a successful
AuditWorkflowResult.

A successful result contains:

- success: true
- nodeCount
- findings

The export functionality is not available for
parser or rule-execution errors.

## Report structure

The generated file contains:

```json
{
  "formatVersion": 1,
  "nodeCount": 0,
  "findingCount": 0,
  "findings": []
}
```

Each finding contains the permitted properties:

- ruleId
- severity
- confidence
- title
- description
- recommendation
- optional nodeIndex

The report preserves the original finding order.

Repeated findings remain separate entries.

## Privacy and data minimization

The report builder creates new objects.

It explicitly copies only the supported fields.

It does not spread the original result or finding
objects into the exported report.

The report does not include:

- Original workflow JSON
- Node parameters
- Workflow credentials
- Local filenames
- Local file paths
- Import history
- Search queries
- Filter selections

Finding titles, descriptions, and recommendations
are exported as generated by the existing audit engine.

The core engine remains responsible for its existing
privacy guarantees.

## Versioning

The report format starts at version 1.

The formatVersion property may support future
report readers.

This step does not implement report import.

## Determinism

The JSON uses two-space indentation and a final
newline.

No timestamps or random identifiers are inserted.

The same successful audit result produces the
same serialized report text.

## Browser download

The implementation creates a Blob using the
application/json;charset=utf-8 MIME type.

A temporary blob URL is created for the download.

A temporary anchor element receives the download
filename:

`workflow-inspector-report.json`

The anchor initiates the browser download.

The temporary element is removed afterward.

The blob URL is released after a short delay.

The browser controls the final file destination
and may adjust the filename if necessary.

## Complete results

Export uses the complete findings array from
the successful audit result.

The export does not use the visible findings
inside FindingList.

Severity filters, confidence filters, text search,
and grouped presentation do not change the report.

## React integration

AuditReportDownload receives the successful result
from App.tsx.

The button uses type=button, so it does not submit
the audit form.

The button is shown only when an audit succeeds.

It is also available when there are zero findings.

It is hidden:

- Before the first audit
- After editing the JSON
- After an invalid submission
- After a parser or audit failure

## Error handling

If the browser download operation throws,
the interface displays:

"The report download could not be started."

The exception message is not displayed.

The interface does not claim that a file has been
saved merely because the download was initiated.

## Limitations

Export is available only for successful audits.

No file is generated automatically.

The download is subject to browser settings.

Some browsers may prompt for the save location.

The generated report is a static snapshot of the
current audit result.

Changing the workflow afterward does not update
an already downloaded file.

The report includes all findings, not only the
subset currently visible through filters.

Existing analysis limitations remain unchanged.
